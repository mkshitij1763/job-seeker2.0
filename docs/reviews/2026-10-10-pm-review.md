## 3. Findings

Format: **ID · Severity · Category · Effort · Persona · Viewport** — what I saw (evidence) → why it matters → recommendation. Severity: P0 broken/blocking, P1 major, P2 moderate, P3 polish. Effort: S ≤ half a day, M 1–3 days, L more. Screenshots in `img/`.

### 3.1 Cross-cutting (every screen)

**PM-001 · P1 · Bug · S · both · all — Validation errors on boosted pages are invisible.**
Settings → Replace resume with a broken PDF → `POST /settings/resume` returns **422** with an error, but nothing on screen changes: no message, same DOM, the bad file still selected. HTMX 2.0.4 doesn't swap 4xx by default and nothing overrides it. Same path: preference validation (`settings.py:75`), resume/facts errors (`:98/:113/:121`), Delete "The email doesn't match" (`:155`), "You're the only admin" (`:159`), CSRF 403 "Request blocked". Onboarding is unaffected (not boosted).
→ Users press a button and nothing happens; they retry or give up. → Set `htmx.config.responseHandling` so 4xx swaps (or `hx-boost="false"` on these forms) and add an `htmx:responseError` toast for 5xx/network errors.

**PM-002 · P1 · Bug · S–M · both · all — Polling updates one fragment; the UI around it goes stale.**
(a) Onboarding resume step: facts appear, but **Finish stays disabled** (`onboarding/resume.html:18` renders `disabled` server-side; polling swaps only `#resume-status`). (b) Job page: after Find contacts finishes, the step card still shows "① Find contacts" with an **enabled primary button**; a reload shows "✓ → ② Approve · Review and approve". img `p1-12`, `p2-08`.
→ (a) New users stall on the last onboarding step; (b) the obvious button starts another paid search. → When a poll finishes, return `HX-Refresh: true` (or out-of-band swaps for the step card / Finish button).

**PM-003 · P2 · Bug · S · both · all — Boosted POSTs leave their URL in the address bar; refresh shows raw JSON.**
After the Settings preview, the URL is `/settings/prefs/where`; refresh/back-forward → `{"detail":"Method Not Allowed"}` (405).
→ Looks broken; on a phone PWA there's no address bar to recover. → Redirect after POST (303 to `/settings?preview=…`) or `hx-push-url="false"` on these forms.

**PM-004 · P2 · UX · S · both · all — Errors are raw JSON pages.**
404/405 render `{"detail":"Not Found"}` with no layout or navigation (owner's job id as roommate, stale links, the 405 above, `/favicon.ico`).
→ Dead end, especially in the PWA. → One HTML error page with the app shell: "This page doesn't exist or isn't yours. Back to Today."

**PM-005 · P2 · Bug · S · both · all — Dates and day counts use UTC, not IST.**
Roommate invited/accepted/joined "2026-10-09" for events at ~05:05 IST on 10 Oct; Zepto "1d since last action" for an event on 8 Oct (2 days in IST).
→ Wrong day every night between 00:00 and 05:30 IST — exactly when the owner checks things. → Format all user-facing dates with `app_now()`/IST.

**PM-006 · P2 · Copy · M · both · all — Internal values leak into the UI.**
Role filter "Ai Pm", "Apm", "Pm", "Founders Office", "Other" (CSS-capitalised keys; onboarding uses "Associate Product Manager", "Founder's Office"); job meta "pm · linkedin · needs contacts"; status pills "drafted", columns "shortlisted 58", Move options "applied via portal", "not interested"; Source filter "ashby, greenhouse, lever"; usage "groq:facts", "score", "tavily".
→ Feels unfinished; vendor names mean nothing to users. → One label map (role family → display name, status → "Shortlisted"…, source → "Company site") used everywhere.

**PM-007 · P2 · A11y · S · both · all — Contrast failures in the token set.**
`--text-3` 2.56:1 (light) / 3.9:1 (dark) on surfaces (chip counts, faint labels, badges); **white on dark-mode accent 3.19:1** (every primary button in dark mode); neutral pill 4.34:1 (light); input/card borders 1.2–1.7:1 (WCAG 1.4.11 needs 3:1), so fields barely read as fields (onboarding step 3).
→ Fails WCAG 2.2 AA; hard to read outdoors on a phone. → Darken text-3 (≥4.5), use a darker dark-mode accent fill (e.g. #4F6BFA) or dark text on it, raise input border/fill contrast.

**PM-008 · P2 · UX · S · both · all — No busy state on any submit.**
Onboarding Continue (~0.6 s full POST), Save where (~1 s swap), Find contacts (page reload, progress below the fold), Fetch now (dead for ~300 ms until the slot loads).
→ People tap twice or think nothing happened. → `hx-disabled-elt="this"` + a spinner/"Saving…" label; disable the button on submit for non-boosted forms.

**PM-009 · P3 · Bug · S · both · all — Flash messages ride in the URL.**
`?msg=Resume%20saved.%20Reading%20it%20now.`, `/today?msg=Already%20queued`, `/admin?msg=Invited%20horizon…&invited=horizon…` (an email address in the URL/history).
→ Messages reappear on refresh/back; PII in history. → Flash via a short-lived cookie/session.

**PM-010 · P3 · A11y · S · both · desktop — Keyboard gaps.**
No skip link (~300 controls on Jobs); inputs show focus only by a 1 px border colour change (buttons/links have a good 2 px outline).
→ → Add a skip link; use the same 2 px outline on inputs.

### 3.2 Landing, sign-in, sign-out, delete

**PM-011 · P1 · Bug · S · both · all — "Delete my account" gives no feedback.**
Typed the email, pressed Delete → nothing on screen changed, though the account *was* deleted (verified). The boosted POST gets 303 → `/login` → 302 to accounts.google.com, which XHR can't follow. img `p1-03`.
→ The most consequential action in the app looks like it failed; users retry or panic. → Non-boosted form, land on a public "Your account is deleted. Your data is gone; backups expire in 4 weeks." page.

**PM-012 · P2 · UX · S · both · all — Sign out lands on Google's account chooser.**
No "You're signed out" page; on a shared device the next person sees the account list.
→ Reads as "sign in again". → Land on the landing page with "You're signed out."

**PM-013 · P3 · Visual/Copy · S · invitee · all — Landing lacks a brand, a link preview and a favicon.**
No product name/logo on the page itself; large empty gap above the privacy text (both themes); no `meta description`/Open Graph tags, so the invite link pasted into WhatsApp previews bare; `/favicon.ico` 404. Lighthouse: A11y 100, Best Practices 100, SEO 50 (noindex intended). img `p1-01`, `p4-01`.
→ The first thing an invitee sees is an unbranded link. → Name + mark on the card; OG title/description/image; favicon.

**PM-014 · P3 · Copy · S · invitee · all — Not-invited page is a dead end.** (D2 PASS)
"This app is invite-only. Ask Kshitij for an invite." with no "Use another Google account" link.
→ → Add "Try another account" (→ `/login?prompt=select_account`).

### 3.3 Onboarding (roommate, from scratch)

**PM-015 · P1 · UX · M · roommate · all — First run ends in an empty app.**
Done card: "Checked 3,285 jobs; 170 match your filters. Your first scores arrive with the next run." → Go to Jobs → **"0 jobs · We're still looking. New jobs arrive after the 11:15 run"** on Apply, Review *and* All; Today says **"All caught up"**; Pipeline all zeros. At 05:10 IST that's a 6-hour wait, and nothing says when. img `p1-14`, `p1-15`.
→ The biggest drop-off risk in the product: the landing promised "read 10 jobs, not 600" and the user sees none. → Auto-queue a Fetch now on Finish; show the 170 matches as "score pending" in Review; give a time ("first scores by ~11:30"); a distinct first-run empty state on Today/Jobs (not "All caught up").

**PM-016 · P1 · Privacy · S · roommate · all — The admin sees the roommate's salary.**
Admin user view shows "Pay: current … · target base …". Onboarding's notice says the admin sees "job preferences and application statuses"; the CTC fields carry no warning.
→ Salary is the item people least expect to share with a roommate; discovering it later breaks trust. → Hide pay from the admin view (preferred) or label the CTC fields "Visible to Kshitij (admin)".

**PM-017 · P2 · UX · S · roommate · all — "Remote within India is fine" is pre-ticked and satisfies the step alone.**
A user who taps Continue on "Where" gets a remote-only search (very few jobs). Remote is a bare checkbox while cities are chips. img `p1-06`.
→ → Default it off, or require ≥1 city unless remote is explicitly chosen; style it as a chip.

**PM-018 · P2 · Bug · S · roommate · all — Back discards the current step.**
Picked Bengaluru + Mumbai → Back → Continue → both gone (Back is a plain link).
→ → Make Back a submit that saves without validating, or keep choices client-side.

**PM-019 · P2 · Bug · S · roommate · all — Years threshold is not pre-filled (spec drift).**
Spec: pre-fill `ceil((years+1)*2)/2` (2.5 for 1.3). Live: stays empty; label "Hide jobs asking for at least __ years" reads like a blank to fill; no explanation.
→ Users invent a number that drives what they never see. → Pre-fill as specced; explain "Jobs asking for more experience than this are hidden".

**PM-020 · P2 · UX · S · roommate · all — "Hide titles containing" is a single-line box with 18 pre-filled terms (spec: removable chips).**
Overflows off the right edge; users can't see what's hidden. img `p1-07`.
→ → Chips with ×, as specced.

**PM-021 · P2 · UX · M · roommate · phone — Step 3 is heavy.**
8 fields (2 required) in one card, ~1.3 screens; must-haves/deal-breakers/summary with no hint of how they're used.
→ Drop-off on phones. → Split optional fields behind "Add more (optional)"; one-line purpose under each.

**PM-022 · P3 · UX · S · roommate · all — Onboarding opens without orientation.**
No welcome or "4 quick steps, ~2 minutes"; the first line is the admin-visibility notice, before the question; "Step 1 of 4" in small mono, no progress bar; card left-aligned at desktop. img `p1-04`.
→ → Welcome line + progress bar; move the visibility notice next to the fields it concerns.

**PM-023 · P3 · UI · S · roommate · all — Resume step mechanics.**
Native unstyled file input (light grey on dark), separate Upload button, Finish disabled with no reason, file input without an accessible name (onboarding only; Settings' has one), file name not shown after upload, banner "Resume saved. Reading it now." stays after reading ends, "Reading your resume…" with no spinner, error text "Pick at least one role" stays after fixing. img `p1-09`–`p1-12`.
→ → Styled drop zone that uploads on select; show the file name; clear stale banners/errors.

**PM-024 · P3 · UX · S · roommate · all — Facts review form is long and partly unlabeled.**
~2,000 px; roles as 4 unlabeled inputs per row inside an unstyled `<fieldset>` (bright default border); "Save facts" (secondary) above "Finish" (primary) — unclear whether Finish saves edits; Save reloads to the top with "Saved" out of view. Copy "Scores and drafts use only these facts" mentions drafts to a user without outreach.
→ → Labels/placeholders per role field; Finish saves; collapse achievements.

**PM-025 · P3 · UX · S · roommate · all — "Enter my skills myself" is only offered after a failed read.** (Checklist D4 partly unreachable.)
→ → Offer it as a link from the start ("No resume handy?").

**PM-026 · P3 · Copy · S · both · phone — Home Screen install signs you out with no warning.** (C1)
iOS gives the PWA its own cookies; the user had to sign in again.
→ → Add "You'll sign in once more in the Home Screen app" to the install hint.

### 3.4 Matching quality (what the app is for)

**PM-027 · P1 · Bug · M · both · all — The scorer ignores seniority.**
Owner (~1.3 yrs): "Principal Product Manager · Sabre" **95, Experience 25/25, Strong match**, top of Find contacts; "Product Manager · Zepto" 97 with Experience 25/25; roommate before-state shortlisted "Principal Product Manager (Target) 77" and "Senior Product Manager – Amazon 77". Watch-outs never mention seniority. img `p2-02`.
→ The product's core promise is judgement; recommending Principal roles to a 1-year analyst wastes Find-contacts quota and the user's trust in every score. → Add explicit seniority to the rubric (title level vs years) with a hard cap on Experience when the title is Senior/Lead/Principal/Staff/Head; show "⚠ Senior role (asks ~8+ yrs)" as a watch-out.

**PM-028 · P1 · Bug · S · both · all — The filter lets through unrelated and senior titles.**
Roommate picked PA/APM/PM; "170 match your filters" includes Inventory Analyst, Clinical Business Analyst, QA Analyst Lead, Senior Incident Response Analyst, Operations Analyst, Lead Data Analyst, Product Control Sr Analyst. Default title exclusions have no "senior", "sr", "lead", "principal", "staff", "head". (Admin user view top-20; onboarding step 3.)
→ Each costs a share of the user's daily scores and clutters Review. → Tighten role-family matching (Analyst ≠ Product Analyst); add seniority words to the default deny list (users can remove them).

**PM-029 · P1 · Data · M · both · all — Naukri contributes 0 jobs on Railway, silently.**
Owner's 05:31 run: every Naukri search failed with HTTP 406 (13×, server logs via devops); the Mac fetched 148 on 10-09. The UI still lists "naukri" as a source and promises Naukri on the landing page; no run note.
→ India's largest job board is missing and nobody can tell. → Surface per-source failures as a run note and on /admin; re-check after the Singapore move (planned).

### 3.8 Pipeline
